# 월간지 구독관리 시스템

> 출판사의 정기구독 도서 주문 · 구독 · 발송을 관리하는 통합 어드민 시스템  
> **프리랜서 1인 개발** | 2025.10 ~ 유지보수 중 (2026.07 실운영 전환)

*이 저장소는 실운영 중인 비공개 저장소를 포트폴리오용으로 공개한 사본입니다. 고객 데이터, 운영 서버 정보, 내부 문서는 커밋 기록 전체에서 제거했습니다.*

---

## 배경
출판사 담당자는 정기구독 · 단품 주문과 복잡한 발송 규칙(합포장, VIP, 주문 유입 경로, 변경 이력)을 엑셀 색칠과 메모로 관리했습니다. 매달 약 3,000건의 명단을 사람이 직접 골라 정리하다 보니 발송 누락이 매달 최대 20건씩 발생했습니다.

이 규칙들을 관리 시스템으로 옮겨, 이제 **6종 도서 × 정기구독 · 단품**과 **3개 판매 채널(Cafe24 · 갓피플몰 · 오프라인)**의 주문을 한곳에서 관리하고 매달 발송 명단을 버튼 한 번으로 생성합니다.

## 성과
- **발송 누락 0건 달성:** 월 약 3,000건의 발송 명단을 버튼 한 번으로 생성해, 매달 최대 20건이던 발송 누락을 0건으로 줄임
- **송장/배송 처리 자동화:** Cafe24 배송 상태 수동 입력(월 100건 안팎)을 제거하고, API 부분 실패 시에도 주문 단위로 격리 처리
- **안정적 실운영:** 2026.07 실운영 전환 후 운영 · 유지보수 중

## 주요 기능
- **발송 명단 생성:** 발행 호(예: `202607`)를 입력하면 결제 완료 주문을 발송 박스 단위로 자동 그룹화
  - 단품은 동일 주소끼리 합포장, 정기구독은 주문 단위, VIP는 전용 슬롯으로 분리 처리
  - 세 흐름 모두 동일한 `SendGroup` 구조를 반환하도록 추상화해 이후 엑셀 추출·송장 처리를 하나로 통일
- **구독 관리:** 구독 기간 연장 · 단축 · 변경, 호 단위 일시중지
- **Cafe24 연동:** OAuth 2.0 인증, 상품 · 주문 가져오기, 배송 상태 자동 변경
- **운영 및 권한 관리:** 고객 · 배송지 · 문의 관리, 주요 활동 로그, 3단계 권한(`SUPER_ADMIN` · `ADMIN` · `MANAGER`)

## 핵심 설계 및 문제 해결
- **구독 기간 이중 필드 설계**
  - 원본 구독 시작 · 종료 호는 수정하지 않고, 연장 · 휴지 · 단축 내역은 실효(Effective) 필드에만 반영합니다.
  - 최초 계약 상태와 현재 상태를 함께 보존하며, 실효 종료 호는 단일 공식으로 일관되게 재계산합니다.
- **상품 성격에 따른 중복 발송 방지**
  - 단품은 발행 호와 관계없이 '전체 발송 이력'으로, 정기구독은 '해당 호의 발송 이력'으로 중복 주문을 필터링합니다.
  - 상품 유형별로 '이미 발송했다'의 비즈니스 기준이 다르다는 점을 반영했습니다.
- **호 단위 일시중지 모델링**
  - 기간 필드를 직접 수정하는 방식 등 4가지 대안을 비교한 뒤, 중지하는 호마다 한 건씩 기록하는 별도 엔티티를 채택했습니다.
  - 언제 몇 호를 쉬었는지 추적 이력이 남고, 누적 중지 횟수만큼 실효 종료 호가 자동 연장됩니다.
- **고객 식별 키 재설계**
  - 가족 구성원이 같은 휴대폰 번호로 각각 구독하는 사례를 반영해, 고유 식별자를 `(전화번호, 이름)` 복합 키로 재설계했습니다.
- **Cafe24 OAuth 보안 및 API Rate Limit 대응**
  - `state` 파라미터 서명 및 유효시간 검증으로 CSRF 위변조를 방지했습니다.
  - 호출 제한에 맞춰 100건 단위 배치로 0.5초 간격을 두고 안정적으로 전송합니다.
- **동시성 제어 기반 JWT 인증**
  - Access · Refresh 토큰을 분리하고, 여러 API에서 동시에 `401` 에러가 발생해도 토큰 갱신 요청은 단 1회만 수행한 뒤 대기 중인 요청을 일괄 재시도합니다.
